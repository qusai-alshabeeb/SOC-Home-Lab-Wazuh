# Wazuh Rule 60122 – Failed Login Detection

## 1. Overview

This document explains the investigation of Wazuh built-in rule `60122`, which detects Windows logon failures involving an unknown username or an incorrect password.

The rule was triggered during a controlled failed-login simulation in the SOC Home Lab.

## 2. Rule Information

| Field | Value |
|---|---|
| Rule ID | 60122 |
| Description | Logon Failure - Unknown user or bad password |
| Severity Level | 5 |
| Windows Event ID | 4625 |
| Agent Name | WIN10-CLIENT-02 |
| Agent IP | 192.168.73.134 |
| Target Username | FakeSOCUser |
| Logon Type | 2 – Interactive |

## 3. Lab Simulation

A failed login attempt was generated on the Windows endpoint using a non-existent local account.

The purpose was to verify that Windows Security auditing was enabled and that Wazuh could collect and detect the resulting event.

## 4. Event Analysis

The following event details were observed:

| Field | Value | Meaning |
|---|---|---|
| Event ID | 4625 | Failed logon |
| Target User | FakeSOCUser | Account used in the simulation |
| Logon Type | 2 | Interactive logon |
| IP Address | ::1 | IPv6 loopback address |
| Status | 0xC000006D | Logon failure |
| SubStatus | 0xC0000064 | User name does not exist |
| Authentication Package | Negotiate | Authentication package |

### Key Findings

- The attempted account did not exist on the Windows endpoint.
- Windows generated Security Event ID 4625.
- Wazuh successfully collected the event and triggered rule 60122.
- The source address `::1` indicates a local loopback connection, not an external attacker IP.

## 5. MITRE ATT&CK Mapping Review

The alert included a mapping to MITRE ATT&CK technique `T1531 – Account Access Removal`.

However, the observed activity was a failed authentication attempt involving a non-existent username.

This behavior does not directly demonstrate account access removal. Therefore, the mapping should be reviewed rather than accepted without validation.

## 6. Analyst Assessment

**Classification:** Expected Lab Activity

The alert was generated by an intentionally simulated failed login attempt.

The collected evidence confirms a failed authentication attempt. No successful login or evidence of account compromise was established from this event.

## 7. Conclusion

This experiment confirmed that Wazuh can collect Windows Security Event ID 4625 and detect failed login attempts using its built-in rule 60122.

It also demonstrated the importance of reviewing alert details and validating MITRE ATT&CK mappings during security investigations.
